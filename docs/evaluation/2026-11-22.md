# PaperRoam 实测与开发记录

使用两篇论文的固定 arXiv v2 PDF，分别取前 8 页，得到 78 个段落。人工标定 5 道中英文问题的标准答案及其证据页和文本锚点。所有答案使用同一 DeepSeek Flash API，最多提供 3 个段落。证据命中以人工标定的选段为准。回答正确且引用正确须同时匹配标准答案、证据编号以及实际发送的上下文。记忆部分使用 4 道独立问题和临时数据库中的合成偏好，两组收到相同论文背景，只有是否提供当前确认记忆不同。

论文：[LongMemEval v2](https://arxiv.org/abs/2410.10813v2)、[PaperQA2 论文 v2](https://arxiv.org/abs/2409.13740v2)。数据与运行配置：[本地重排逐题 JSON](2026-11-22-local.json)、[API 重排逐题 JSON](2026-11-22-api.json)。

## 开发中遇到的核心问题

- Windows 默认 Python 缺少 pip。改用已安装的 CPython 3.12 创建独立环境。MiniLM 首次下载出现 TLS 断连，重试时禁用 Hugging Face Xet 路径，下载完成并通过本地推理。CLI 保留 API 重排可选项。
- 有证据编号的结论仍可能引用错内容或带入原文没有的数字。现在逐条核对原文摘录和数字，并显示 PDF 页码、版本和摘录。语义是否充分支持结论仍需核读。
- 代码审查复现了三条失败路径：带手动聚焦词的主题全文检索会被拦截，指定版本下载失败没有摘要回退，补搜的空结论会覆盖首轮结果。修复后，聚焦词独立于学术检索词，失败时读取同版本 arXiv 摘要，并保留已核对的首轮摘录。
- 长期记忆与跨聊天推理容易混在一起。单次聊天保留最近两轮，长期只记明确确认过的记录。同键更正保留旧版，默认查询取当前版。另开聊天需显式选择是否带入已确认的旧记忆。
